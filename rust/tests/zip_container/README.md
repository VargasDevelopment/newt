# Shared ZIP catalog and entry reader

`newt-core::zip_container` contains the actual parser and reader. Host transport,
focused tests and runtime-borrowed target probes use that same module. The
mandatory `zip_container_gate.py` family validates all70 independently frozen
case identities, original C++/Rust complete responses and10 fresh semantic
mutants. It preserves every earlier family and both exact nonempty target exports.

The frozen original SDK parser is unchanged. The oracle adapter supplies a
synthetic source/arenas and optionally calls Catalog.open twice (`--reopen`);
no parsing/reader algorithm is duplicated. Request grammar has nine canonical
fields (see protocol.py). Responses include full destination bytes and ordered
source calls. Both C++ byte-arena and Rust typed-slot/name-arena facts are
validated and retained separately, including actual host record sizes. Capacity
mapping, stable-input/entry and C definedness limits are in CONTRACT.md.

The default native host inflater branch is64bits; lower-level inflater parity
already covers both32/64 branches. Borrowed RV32catalog/reader compilation is
not execution, linked firmware or resource acceptance. No caller state/dictionary
construction is hidden in those probes. Heap/stack, whole-reader memory, panel,
power, firmware size and device performance remain separate unfinished work.
