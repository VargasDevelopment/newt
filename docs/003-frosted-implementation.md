## Separate four-level display integration

Use the unchanged official FreeInk pin `cd6f5b831c8fad899723b6d406586f00c575f021`. Its [display facade](../vendor/freeink-sdk/libs/display/FreeInkDisplay/include/FreeInkDisplay.h) exposes mode-bound grayscale capabilities, native-plane strip uploads and cleanup. Query the detected panel's actual mode capabilities and success returns; a scalar four-tone PNG is not a native-plane upload test. The actual X3 paths are [UC8253](../vendor/freeink-sdk/libs/display/FreeInkDisplay/src/driver/Uc8253X3Driver.h) and [UC8279D](../vendor/freeink-sdk/libs/display/FreeInkDisplay/src/driver/Uc8279Driver.h), not the A4 UC8279C driver.

Both X3 paths expose four levels and strip uploads, but no asynchronous grayscale base or staging while busy. The generic [window fallback](../vendor/freeink-sdk/libs/display/FreeInkDisplay/src/driver/PanelDriver.h) calls full-frame FAST, so cheap dialog-only glass updates are unproved. Do not infer that ordinary facade async APIs make grayscale asynchronous or permit overwriting busy state.

For the first decorative candidate, retain the [host probe's](host-blur-probe.md) half-resolution Gaussian and separate quantization. Its 4,818-byte portrait scratch and host timings exclude plane packing, SPI/waveform and runtime heap costs; native-row scratch is approximately 7,227 bytes before strips/other SDK work. No second full snapshot or full 8-bit framebuffer is budgeted. Use cooperative row work, compute once per page/layout identity, preserve crisp opaque controls, and make Back/Sleep cancellation restore the saved reading anchor. A persistent native gray background and its buffer ownership must be proved before accepting repeated focus updates; do not blur or refresh the background repeatedly for focus.

Absolute/Direct grayscale requires ordered complete coverage of both native planes (792 × 528, 99 bytes per row). Respect each mode's distinct [plane encoding](../vendor/freeink-sdk/libs/display/FreeInkDisplay/include/GrayscaleCapabilities.h); Overlay relies on its B/W base, and encoding alone does not guarantee independence from prior ink. Output inversion disables grayscale capability. After uploads, use the SDK's required controller-RAM/baseline cleanup when returning to black/white, cancelling or sleeping. UC8253 Direct invalidates the baseline and requires stronger B/W recovery; UC8279 Absolute/Direct also retain a forced next-refresh requirement after cleanup. Such work takes precedence over the adjustable five-reading-page cadence. Track display-mode state explicitly and test cleanup on error/cancellation, without modifying upstream SDK sources. Keep a plain black/white presentation available if capability, memory, latency or panel quality fails. Floyd–Steinberg is an unimplemented alternate to evaluate only if needed; Bayer diagnostics are not the selected appearance.
